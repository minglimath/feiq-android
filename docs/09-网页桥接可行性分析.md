# 网页桥接可行性分析

目标：在浏览器里打开一个网址，就能自动发现局域网里的飞秋设备，并收发消息和文件。

## 结论

**必须有「桥」**：一个跑在局域网里、能开原始 socket 的进程。浏览器自己做不到。

但「桥」不等于要额外买服务器——**机顶盒（Ubuntu）是最合适的落点**。

## 为什么浏览器自己做不到

1. **没有 UDP API**。飞秋的发现完全依赖 UDP 广播到 2425（`Protocol.DEFAULT_PORT`），浏览器发不了 UDP 包。
2. **不能发任意 TCP 二进制协议**。`fetch`/XHR 只能说 HTTP，WebSocket 只能说 ws(s)；飞秋传文件是裸 TCP（发 `GETFILEDATA` 后直接流式传字节，见 `TcpFile.kt`）。
3. **WebRTC 也不行**。它要求对端也是 WebRTC 端点，原生飞秋不是。
4. **Private Network Access**。Chrome 对「公网页面 → 局域网地址」的请求要求目标返回 `Access-Control-Allow-Private-Network: true`，所以页面必须由局域网内的服务自己托管（私网→私网、同源）。

唯一的技术例外是 Chrome 的 **Direct Sockets API**，但它只对 Isolated Web App（需签名打包安装）开放，普通网页用不了，不值得考虑。

## 为什么机顶盒 Ubuntu 比安卓当桥更好

| | 安卓当桥 | 机顶盒 Ubuntu 当桥 |
| --- | --- | --- |
| 原始 socket | 受限 | 完整 |
| 保活 | 前台服务 + Doze + WakeLock | 普通常驻进程 |
| 存储 | 分区存储 + MANAGE_EXTERNAL_STORAGE | 普通 Linux 文件系统 |
| 常电常开 | 不一定 | 天生如此 |
| 更新 | 重新打包 APK 装机 | `git pull` + 重启 |

Android 上最痛的那些限制，在 Linux 上全部消失。

## 关键发现：协议层几乎可以直接移植

排查 `net/` 整个包对 Android 的依赖，结果只有 3 个文件、各一行：

```
UdpChannel.kt:3           import android.util.Log
TcpFile.kt:3              import android.util.Log
InlineImageReceiver.kt:3  import android.util.Log
```

其余（`Protocol`、`PacketCodec`、`FileListCodec`、`DirFileCodec`、`FeiqRichText`、`FeiqEmoticons`）**零 Android 依赖**；`core/FeiqEngine.kt` 的唯一 Android 依赖同样只有 `android.util.Log`。网络层用的是标准 `java.net`。

所以只要给 `android.util.Log` 提供一个垫片，这些代码就能**原封不动**跑在桌面 JVM 上。

## `:bridge` 模块怎么做的

`android/bridge/` 是一个纯 JVM（`kotlin("jvm")` + `application`）模块，**不复制协议源码**，而是用 `srcDirs` 直接复用 app 模块的 `net/` 和 `core/`，再 `exclude` 掉 Android 专属文件：

```kotlin
sourceSets["main"].kotlin.srcDirs(
    "../app/src/main/java/com/feiq/droid/net",
    "../app/src/main/java/com/feiq/droid/core",
)
sourceSets["main"].kotlin.exclude("**/App.kt", "**/Prefs.kt", "**/Storage.kt", ...)
```

这样**协议实现只有一份**，安卓端和桥不会分裂。

垫片在 `bridge/src/main/kotlin/android/util/Log.kt`，只实现源码里用到的 `d/i/w/e`。默认只输出 `e`，加 `-v` 打开全部协议日志。

> 注意：以后往 `core/` 里新增 Android 专属文件时，要同步补进 `bridge/build.gradle.kts` 的 exclude 列表，否则桥会编译失败。

## 怎么跑

```bash
cd android
./gradlew :bridge:installDist
bridge/build/install/feiq-bridge/bin/feiq-bridge [端口] [昵称] [-v]
```

机顶盒上需要先装 OpenJDK 17。CI 会把 `feiq-bridge` 分发目录作为 Artifact 上传，可以直接下载拷过去。

## 机顶盒上要注意

- **2425 端口**：机顶盒上没跑别的 IPMsg 客户端的话是空闲的。用 Docker 必须 `--network host`，否则 NAT 会让 UDP 广播出不去。
- **多网卡选出口**：机顶盒常同时有有线和无线，广播要选对网卡（当前实现用的是 `255.255.255.255` 全局广播，多网卡环境下可能需要在 `UdpChannel` 里显式绑定网卡）。
- **防火墙**：`ufw` 默认可能拦 2425/8080，要放行。
- **CPU 架构**：机顶盒多为 ARM64，OpenJDK 有 aarch64 版本。
- **mDNS**：机顶盒一般有 `avahi-daemon`，可以起 `feiq.local` 之类的名字，二维码写 `http://feiq.local:8080`，IP 变了也不用改。
