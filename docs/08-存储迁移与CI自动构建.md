# 存储迁移与 CI 自动构建

## 背景

- 原来所有数据都写在应用私有目录，Android 11+ 的 `Android/data/...` 在文件管理器里被隐藏，用户拿不到接收到的文件。
- 目标一：把存储目录改到公共的 `Download/FeiQ`，文件管理器和数据线都能直接看到。
- 目标二：推到 GitHub 后由 Actions 自动编译 APK，不用每次本地出包。

## 方案选型

`targetSdk = 34` 会触发分区存储，Android 10+ 不能直接用 `File("/sdcard/Download/...")` 写公共目录。三条路线：

- **MediaStore / SAF**：免特殊权限，但返回 `content://` 而非 `File`，需要改造打开/预览/存在性判断，且文件夹传输在 MediaStore 下不好建目录树。
- **MANAGE_EXTERNAL_STORAGE（采用）**：改动最小，保留全部 `File` 真实路径逻辑；代价是用户要手动在系统设置里授权，且**不能上架 Google Play**。本项目是个人使用、侧载分发，可以接受。
- **只迁接收文件 + 导出**：未采用，用户要求全部数据可见。

## 存储结构

统一根目录 `Download/FeiQ`：

| 内容 | 旧路径 | 新路径 |
| --- | --- | --- |
| 接收文件/文件夹 | `Android/data/com.feiq.droid/files/Download/received/` | `Download/FeiQ/received/` |
| 聊天记录 JSON | `/data/data/com.feiq.droid/files/chat/` | `Download/FeiQ/chat/` |
| 图片（收发图/内联图/表情） | `/data/data/com.feiq.droid/files/images/` | `Download/FeiQ/images/` |
| 头像 | `/data/data/com.feiq.droid/files/avatars/` | `Download/FeiQ/avatars/` |
| 导出聊天记录 | `Android/data/.../files/Documents/backup/` | `Download/FeiQ/backup/` |
| 拍照临时文件 | `/data/data/.../files/camera/` | 不变（临时文件，无需可见） |
| 保存到相册 | `Pictures/FeiQ` | 不变（本来就可见） |

## 权限流程

- **API 30+**：用 `Environment.isExternalStorageManager()` 判断，未授权时跳 `Settings.ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`。
- **API 29 及以下**：走 `WRITE_EXTERNAL_STORAGE` 运行时申请；API 29 依赖 `requestLegacyExternalStorage` 保留传统存储行为。
- **未授权时**：自动回退到 `getExternalFilesDir(null)/FeiQ`，应用功能完全不受影响，只是文件对其他应用不可见。
- 首次启动弹一次说明对话框（`去授权` / `暂不`），进程内只提示一次。

## 数据迁移与回退读取

迁移只**拷贝、不删除**源目录，所以旧记录里的绝对路径（`filePath` / `imagePath` / 头像路径）仍然有效。成功一次后写 `storage_migrated` 标记，不再重复执行。

一个必须说明的坑：如果只是简单切目录，旧历史在公共目录尚不存在时会被 `MessageStore.load()` 读成空并缓存，之后任何一次保存都会用「空 + 新消息」覆盖掉旧记录，造成**历史丢失**。因此 `MessageStore` 改为：

- `load()` 优先读新目录，新目录没有该对端文件时回退读旧内部目录；
- `listPeers()` 取新旧两个目录的并集；
- `deletePeer()` 新旧都删。

这样即使迁移尚未完成或中途失败，数据也不会丢。

## GitHub Actions

文件：`.github/workflows/android.yml`

- 触发：`push`（`main`/`master`）、`pull_request`、`workflow_dispatch`，以及 `v*` 标签。
- 步骤：checkout → JDK 17 (temurin) → `android-actions/setup-android` → 安装 `platforms;android-35` 与 `build-tools;36.0.0` → `gradle/actions/setup-gradle` 缓存 → `./gradlew assembleDebug`。
- 产物：`feiq-android-debug` Artifact，内含 `app-debug.apk`。
- 打 `v*` 标签时用 `softprops/action-gh-release` 自动发布到 Releases。

产物是 **debug APK**（debug 签名，可直接安装）。release 构建未配置签名，装不上，所以没有纳入 CI。

## 已知风险

- **Gradle 9.1.0 + AGP 8.13.1 是未经本机验证的组合**。AGP 8.13 官方最低要求 Gradle 8.13，9.1.0 高于最低要求通常可用；若 CI 报不兼容，把 `android/gradle/wrapper/gradle-wrapper.properties` 的 `distributionUrl` 改成 `gradle-8.13-all.zip`。
- `MANAGE_EXTERNAL_STORAGE` 需要用户手动开启，部分定制 ROM 有限制；未授权时走回退目录，功能可用。
- 迁移不删除源目录，设备上会保留一份重复数据。
- 仓库的 `Settings → Actions → General → Workflow permissions` 需要是 **Read and write**，否则 tag 发 Release 会被拦（只下载 Artifact 不受影响）。
